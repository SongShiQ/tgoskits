**调试中发现的关键问题**：

**rdev 问题**：
- `busybox rdev -h` 在 StarryOS QEMU 中返回 rc=1 但输出为空
- `busybox rdev` 同样输出为空
- 原因：rdev 读取 `/proc/kcore` 等内核接口，StarryOS 可能未实现
- 修复：不依赖输出内容，仅验证 applet 不 hang（rc≠124）

**resize 问题**：
- `busybox resize 2>&1` 输出包含终端转义序列 `^[7^[r^[999;999H^[6n`
- 这些转义序列把 `EXIT:1` 标记挤到非行首位置，sed 无法匹配 `^EXIT:`
- 修复：`busybox resize >/dev/null 2>&1` 吞掉所有输出，只捕获返回码

**riscv64 static-pie 段错误根因定位（修正后）**：
- 编译最小 C 程序（仅 printf）为 static-pie（Type=DYN），注入 riscv64 rootfs
- QEMU 运行：最小程序也 segfault（RC=139），确认是 loader 问题非 llama.cpp 问题
- 崩溃 PC=0x3b0 是 `.plt` 段起始地址（`.text` 在 0x3f0），非 entry point
- binary 有未处理的 PLT 重定位（`puts`, `__libc_start_main` 的 `R_RISCV_JUMP_SLOT`）

- 结论：需要在 loader 中添加 relocation processing，是内核 loader 增强
- 分支：`fix/riscv64-static-pie-segfault`，root cause 文档已提交

**riscv64 static-pie ELF loader relocation 实现**：
- 设计确认：loader.rs 无 relocation 处理、static-pie 存在 PT_DYNAMIC、实际出现 R_RISCV_RELATIVE + R_RISCV_JUMP_SLOT
- 实现：在 map_elf() 后添加 apply_relocations()，使用 CachedFile.read_at() 读取 dynamic section 和 relocation entries
- 支持类型：R_RISCV_RELATIVE (base + addend)、R_RISCV_JUMP_SLOT (从 .dynsym 查找符号地址)
- 编译验证：cargo check PASS、cargo xtask starry build --arch riscv64 PASS
- Commit `3b67ca0b0`，修改文件：loader.rs (+199 行)

**R_RISCV_64 重定位支持**：
- 编译 riscv64 static-pie 最小程序后检查 relocation entries，发现除 R_RISCV_RELATIVE 和 R_RISCV_JUMP_SLOT 外，还有 R_RISCV_64 (type=2) 条目
